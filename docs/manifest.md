# Manifest for the viewer (contract with the project)

Copyright © 2026 - Simone Caporale

The files a project writes and the viewer reads. The viewer itself is described in [viewer.md](viewer.md); the command that
writes the manifest is in [publishing.md](publishing.md).

The viewer page (`containers/viewer/www/index.html`) is generic: it reads only these files, written by the project. Everything is
optional except `files`; a missing field is not shown.

`out/releases/v<V>/manifest.json` (one folder per version; `out/releases/latest` = link to the latest):

| Field | Contents |
|---|---|
| `schema` | 1 |
| `version`, `branch`, `built_at`, `updated_at`, `release` | version, git branch, ISO 8601 UTC dates, `true` for a release |
| `files` | `{name: {group, type: file\|dir, files, bytes, sha256, produced, kind}}`: the `.d64` files among them get the vc64web / VICE / download buttons; a `.sid` file or a folder with `kind: "sid"` gets **♪ play**: the **SID Studio** page (`sid.html?src=out/...`). Library always at hand on the left (the release tunes, plus the user's own `.sid` files added with a button or drag and drop: with the jsSID source read in the browser and never uploaded; with the reSID source sent to the local container, see below), transport with subtunes, end-of-length mode CONT / NEXT (auto-advance) / LOOP, length, 6581/8580, **video standard AUTO / PAL / NTSC** (AUTO follows the clock flags of the PSID header, PAL when they say unknown or both; PAL = 985248 Hz and 50 Hz, NTSC = 1022727 Hz and 60 Hz: pitch, ADSR times and the play routine rate follow; the standard in use and its source are in the player info; changing it restarts the subtune), volume, WAV recording of what you hear (**● REC**, real time) and **⇩ WAV**, an offline export: the chosen length (the length field or a fixed one) is rendered faster than real time with an `OfflineAudioContext` and the same worklet, with the page's tune, subtune, 6581 / 8580, video standard, mute / solo, SID filter on/off, override, EQ and tone preset, then downloaded as a 16-bit mono WAV; progress, time taken and speed factor are shown; the button is disabled, with a tooltip, where AudioWorklet is not available (see Sound engine); around it: analog VU meter (IEC 60268-17 ballistics, 0 VU = −18 dBFS, peak LED), 1/3-octave spectrum with peak hold and the SID filter curve (approximate), player CPU (cycles of the play routine per frame, jsSID estimate), a channel strip per voice (scope, envelope with its phase, waveform, note, ADSR, routing, mute / solo) and a master strip (mix scope, SID filter on/off), piano roll of the last 10 s, automation lanes (pulse widths, cutoff), spectrogram, monitor tone presets and 3-band EQ, **SID filter override** (every part of the chip filter follows the tune or is forced: LP / BP / HP, routing of each voice, voice 3 off, cutoff, resonance, volume, with presets; the registers are changed only around the sound computation, the tune keeps its own values; meters, master strip and filter curve show what is heard), live register table $D400-$D418 with changes highlighted. The desk is a coarse grid (12 columns x units of 100 px): every panel can be moved (drag its ⠿ grip), resized only to the sizes allowed for it (size button `W×H`: click = next, shift+click = previous; or drag the ◢ corner, which snaps), collapsed to its header; the VU meter has a fixed size; the others flow and fill the holes; the layout is kept in the browser and **⟲ VIEW** restores the default. Library and top bar stay fixed. **Sound engine**: jsSID runs inside an **AudioWorklet** (audio thread), so the drawing of the page cannot make it crackle; the top bar says which engine runs (`jsSID · worklet`). `www/sidengine.js` is the main-thread side: an object with the API of jsSID that sends commands to the processor and receives, about 60 times a second, the registers `$D400-$D41F`, envelopes, filter registers, play routine cycles, play time and the scope samples (in a `SharedArrayBuffer` only when the page is `crossOriginIsolated`, which the viewer server does not ask for: normally copies). Without AudioWorklet (**it needs a secure context: `https`, or `localhost`; a viewer opened over plain `http` from a host name of `VIEW_HOSTS` does not have it**) the page falls back to jsSID's ScriptProcessor on the main thread (`jsSID · script`); `sid.html?src=...&engine=script` forces it. Two themes in the top bar: **studio** (dark desk) and **commodore** (the control center look: cream paper, red, rainbow stripes, light / dark following the choice of the index page). **Audio source**: a selector in the top bar, **jsSID · live** (default, everything above) or **reSID · rendered**, remembered in the browser. With reSID, jsSID is stopped and the tune is rendered by `sidplayfp` (reSIDfp, `containers/tools/py/sidrender.py`) in the local `lab64-player` container through `POST /render` (see [viewer.md](viewer.md#render-endpoint)); the WAV is decoded and played by an `AudioBufferSourceNode` into the **same chain** as jsSID, so volume, EQ, tone presets, VU, spectrum, spectrogram, master scope and **● REC** work on it. The transport works on the rendered file: play / pause / stop, prev / next, subtune, CONT / NEXT / LOOP (CONT stops at the end of the file: a render lasts LEN; LOOP restarts it without rendering), **LEN**; changing the subtune, LEN, the chip model or the video standard renders again ("rendering… N s (~%)", then it plays). **SID model** gets an AUTO (follow the tune's header, 6581 when it says nothing) and so does the video standard; a choice other than AUTO is *forced* on sidplayfp (`-mof` / `-mnf`, `-vpf` / `-vnf`). A release tune with the default settings (AUTO, reSIDfp, filter on, no mute, 3:00) plays its published MP3 when `C64_PUBLISH_SID_RENDER` made one; any other setting renders. The **reSID panel** (a band under the top bar, only in reSID mode, so the desk keeps its layout): engine (reSIDfp / sidlite), filter curve (light 0.8 / medium = default 0.5 / dark 0.2 / auto, or a number 0 dark .. 1 bright), filter range (default / auto / number), combined waveforms (weak / average / strong), digiboost, 6581 old caps, WAV format (16-bit or 32-bit float, for the download only), **⟳ render** and **⇩ WAV** (the rendered file, rendered first when the current settings differ). Mute (M) and the master **sid filter** checkbox map to `-u` and `-nf`, and so do the panel settings: they do not play until the next render, and the render button says what changed (`⟳ render · mute, curve`). **Analyzer**: a second jsSID, silent (AudioWorklet `jssida`, no noise floor, no dither, through a `GainNode(0)`), is started at the same context frame as the WAV (`AudioBufferSourceNode.start(T, offset)`, both at a frame-rounded `T`) and feeds the registers, envelopes, per-voice scopes (badge `jsSID synthesis`), voice info, player CPU, piano roll, automation lanes; the panels say `analyzing…` until it is locked. Its clock is scaled by two constants, 0.999796 (PAL) and 0.999604 (NTSC), measured for sidplayfp 3.2.3 at 44.1 kHz (sidplayfp's WAV is stretched by that factor; the page's own re-lock covers a change), and it starts when sidplayfp's first play call happens (computed from the cycles of the init routine, calibrated on the four `cal_*` tunes: PAL / NTSC x VBI / CIA). Seeks and subtune changes restore the nearest checkpoint (the state every 10 s, built in the Web Worker `www/sidck.js` with the same patched core, 18 checkpoints for 3:00 in about 10 s) and fast-forward the rest in slices of at most 0.05 s of emulation per 128-sample block, so the audio thread never stalls. The telemetry is delayed by the output latency (`getOutputTimestamp`), so the panels move with what is heard; if the analyzer's play time and the WAV position differ by more than 20 ms (any scheduling error) the page re-seeks it. **A/B** (button or key B): crossfade of 10 ms between the WAV and the analyzer at the same position (the header says which engine is heard; the one not heard keeps running silent). **Greyed, not hidden, with a tooltip that says why**: solo (S), the SID filter override panel (the rendered sound would not follow them), the filter curve over the spectrum, and the top-bar jsSID **⇩ WAV** export. The header says which engine runs (`reSIDfp · rendered` or `jsSID · worklet` / `script`). A user's file dropped in the page is sent to this local container to be rendered: a dialog says "the file is sent to your local Lab64 container to be rendered with reSID; it does not leave this computer" before the first upload (answer kept in the browser). The control center links it from "Try it yourself" (**♪ SID Studio**, opened on the music of the newest version) |
| `groups` | `{group: label}`: how to show the groups of `files` and `missing` |
| `missing` | groups not generated in this version |
| `tests` | `{ran, suites[], total, pass, fail, skip, seconds}`; the details in `test_report.json` (`{suites, total_s, results: [{id, suite, desc, result PASS\|FAIL\|SKIP, reason, time}]}`) |
| `stats.metrics` | project measures: `[{id, label, value, unit: B\|s\|"", better: up\|down\|null, hint}]` (cards, trends, comparison) |
| `stats.info` | `[{label, value}]`: data to show and compare, with no chart |
| `stats.disk` | `{blocks_total, blocks_free, blocks_used, files: [{name, type, blocks}]}` (disk directory) |
| `stats.git` | `{commit, subject, dirty}` |
| `stats.build_seconds` | build duration |

Live status, in `out/tmp/` (rewritten atomically: temporary file and rename):
- `build.json`: `{state: running|ok|fail, phase, flags, started, updated}` (times in Unix seconds);
- `tests.json`: `{state: running|ok|fail|aborted, suites, filter, total, started, updated, seconds, current: {id, suite, desc, since}, results: [as above], caps, error}` (`error` only when aborted).
