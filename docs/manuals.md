# Instruction manuals

Copyright © 2026 - Simone Caporale

`lab64 manual`, implemented by `containers/pdf-gen/c64manual.py` (themes in `containers/pdf-gen/themes/`), runs in the
`lab64-pdf-gen` image. The settings are in [configuration.md](configuration.md).

Source: an HTML file where every `<div class="page">` is one page; a page with the class `cover` is not numbered. The generator
fills `{{NAME}}` placeholders (values from a project script), links relative files (next to the source, else in the output
folder: pictures generated by the build), puts the theme into the page, draws every `<kbd>X</kbd>` as an SVG key cap (text
centred exactly), numbers the pages, writes HTML + PDF (WeasyPrint) and reports pages whose content is cut
(`--strict`: exit 1, for release builds; with `--strict` an overflow check that cannot run, since it uses WeasyPrint internals,
is an error too).

## Several manuals

Languages, a full and a short one, two formats: one source each. `C64_MANUAL_SRC` lists them (space
separated, patterns allowed: `"manual/*.html"`); `lab64 manual` builds them all in one run, or the ones given as arguments.
Every source can carry its own settings in its `<head>`:

```html
<meta name="lab64:format" content="A4">        <!-- A4, A5 (default), A6, Letter, or <w>x<h> in mm -->
<meta name="lab64:base" content="plain">       <!-- Lab64 base theme, or "none" -->
<meta name="lab64:theme" content="short.css">  <!-- project theme, relative to the source -->
<meta name="lab64:pdf" content="Game_EN.pdf">  <!-- PDF file name -->
```

Order: command option > meta of the source > `lab64.env` (`C64_MANUAL_FORMAT`, `C64_MANUAL_BASE`, `C64_MANUAL_THEME`,
`C64_MANUAL_PDF`) > default.

## Page format

It reaches the PDF as CSS: the generator writes `@page { size: W H }` and the page box size (`--page-w`,
`--page-h`) between the base theme and the project theme, and WeasyPrint lays out every `div.page` on a sheet of that size. The
type sizes are those of the theme: the same text does not fit two formats, so an A4 manual is another source (its own text and,
usually, its own theme with other sizes and margins).

## Themes

Base themes of Lab64: `c64` (cream paper, red accents, dark cover, monospace type, tables, figures, notes, `.cmd` for
what the player types) and `plain` (black on white, no filled areas: cheap to print; it extends `c64`). The project theme is
loaded after the base one, so a project can:
1. change only the **variables** (`--paper`, `--ink`, `--accent`, `--cover-bg`, `--cover-title`, `--font`, `--size`, `--key-face`, ...);
2. **add rules** for its own elements, or override single rules;
3. **replace** the whole style: base `none` (then the project CSS is the only style);
4. pick another base theme by name. A new base theme is a CSS file in `containers/pdf-gen/themes/`; `/* lab64:extends c64 */` at its top
   loads a parent first.
A `<link rel="stylesheet">` in the source still works and comes last.

## Generated content

A project with generated content (tables from its data, cropped screenshots) writes a small script, runs it with `C64_MANUAL` and
calls `c64manual.build(src, values={...}, theme=..., out_dir=..., pdf_name=..., fmt=..., strict=...)` once per manual.
